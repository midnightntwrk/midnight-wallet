## High-level summary

This patch release moves the SDK to the final `@midnightntwrk/ledger-v9` 1.0.2 and proof server 9.0.2. It fixes a facade
that released a submitted transaction's coins and Dust on errors raised after the transaction was in a block,
transactions that needed more proofs than a proof server queues, and shielded and Dust wallets that stopped syncing or
never reported synced. The in-process prover now proves ZKIR v3 circuits, and the Dust wallet exports
`dustWalletProbes`.

## Audience

This release is for:

- **External integrators** who build wallets on Midnight, move tokens from their DApps, or manage shielded, unshielded
  and Dust balances.
- **Shielded Technologies** engineering teams who maintain the SDK, its test harness or services built on it.

## Dependencies

Hard, component-local requirements:

- `@midnightntwrk/ledger-v9` is pinned to exactly `1.0.2`, where 2.0.0 accepted `^1.0.0`; `@midnightntwrk/ledger-v8`
  stays at `^8.1.3`.
- The prover client depends on `@midnightntwrk/zkir-v3` `^3.2.1`, whose runtime is loaded only when a ZKIR v3 circuit is
  proved.
- The SDK is tested against proof server 9.0.2 for ledger-v9, node 2.1.101 and indexer 4.4.101.

**Downstream impact (cascading effects).**

- ledger-v9 from 1.0.1 refuses to price a transaction that repeats a spend, so `estimateFee` and `balanceTransactions`
  on the V2 variant fail on such input. ([#938](https://github.com/midnightntwrk/midnight-wallet/pull/938))

## What changed

- The SDK runs the final `@midnightntwrk/ledger-v9` 1.0.2 and proof server 9.0.2; ledger-v9's key material is unchanged,
  at circuit generation 10. ([#946](https://github.com/midnightntwrk/midnight-wallet/pull/946))
- `WalletFacade.submitTransaction` keeps a submitted transaction's coins and Dust booked unless the failure proves no
  block holds it. ([#925](https://github.com/midnightntwrk/midnight-wallet/pull/925))
- The HTTP prover client holds at most 10 requests at a proof server at once and sends a request again when the proof
  server's queue is full or it answers 502, 503 or 504.
  ([#933](https://github.com/midnightntwrk/midnight-wallet/pull/933))
- The in-process prover proves contract circuits compiled with compactc 0.36.0 or later, which emit ZKIR v3 only.
  ([#928](https://github.com/midnightntwrk/midnight-wallet/pull/928))
- A Dust wallet on the projections sync keeps synchronizing when a pass hands back a coin it already applied.
  ([#935](https://github.com/midnightntwrk/midnight-wallet/pull/935))
- Restoring a Dust snapshot refuses one holding values the wallet cannot use, with `SnapshotRestoreError`
  (`invalid-shape`), on both variants. ([#936](https://github.com/midnightntwrk/midnight-wallet/pull/936))
- A shielded wallet on a chain whose zswap commitment tree is still empty reports synced.
  ([#927](https://github.com/midnightntwrk/midnight-wallet/pull/927))
- `dustWalletProbes(configuration)` is exported, so a composition with its own variants starts its Dust where
  `DustWallet` would. ([#875](https://github.com/midnightntwrk/midnight-wallet/pull/875))
- The test harness network presets point at their `shielded.tools` hosts.
  ([#911](https://github.com/midnightntwrk/midnight-wallet/pull/911))
- A test harness wallet lifecycle released with `persist: false` deletes the sync cache snapshots it would have saved.
  ([#942](https://github.com/midnightntwrk/midnight-wallet/pull/942))

## New features

### `dustWalletProbes`

**Description**: `dustWalletProbes(configuration)` returns the probes `DustWallet` asks before a fresh start, including
the search for where the Dust timeline reaches `forks.v9` when `skipLedgerV8DustHistory` is set. A composition with its
own variants spreads it into its configuration to start where `DustWallet` would.

### Proof server request cap and retry settings

**Description**: The HTTP prover client takes `maxConcurrentRequests`, the most requests it has waiting at a proof
server at once (10 by default), and `retrySchedule`, how it waits before sending a request again (1 second, doubling up
to 10 seconds, for 5 minutes in all, by default). A wallet sets the cap per proof server backend, with
`maxConcurrentRequests` beside `url` in `provers`, and `ServerProvingConfiguration` takes it too; `provingServerUrl`
always uses the default. `HttpProverClient.create` and `HttpProverClient.layer` can now also fail with
`InvalidMaxConcurrentRequestsError`, when `maxConcurrentRequests` is not a whole number of at least one. A request the
proof server has not answered within 10 minutes is given up, which fails the proof. This limit is fixed and matches the
proof server's default job timeout.

### Test harness `willRetry`

**Description**: Passing `willRetry(context)` as `willRetry` keeps the sync cache snapshots of a failed attempt that
vitest will run again, honouring the test's retry `condition`. The dust and token-transfer healthchecks pass it.

## Improvements

### ledger-v9 1.0.2 and proof server 9.0.2

**Description**: `@midnightntwrk/ledger-v9` moves from the `^1.0.0` range to the final `1.0.2`, run with proof server
9.0.2. The test stacks move to node 2.1.101 and indexer 4.4.101.

### Test harness wallets on networks past the v9 fork

**Description**: The test harness's `eventLessDustWallet` takes its probes from `dustWalletProbes`, so it honours
`skipLedgerV8DustHistory` as `DustWallet` does. The remote network presets set that flag, so a new wallet on a network
that crossed the v9 fork starts its Dust at the boundary instead of replaying the ledger-v8 history; the undeployed
environment leaves it off.

### Test harness network presets

**Description**: The `devnet` and `qanet` presets use `*.<network>.shielded.tools` hosts, which resolve to private
addresses and need the VPN. The `preprod` preset moves to `indexer.preprod.shielded.tools` and
`rpc.preprod.shielded.tools`, and the `preview` preset is unchanged. Any preset host can be replaced through
`createRemoteEnvironment`'s `endpoints` option.

## Known issues

- [#742](https://github.com/midnightntwrk/midnight-wallet/issues/742): The shielded wallet's sync retry back-off is not
  capped, so after a long indexer outage the shielded sync can wait far longer than two minutes between attempts.
  Workaround: restart the wallet once the indexer is back.
- [#743](https://github.com/midnightntwrk/midnight-wallet/issues/743): The shielded and Dust wallets are not gated by
  indexer liveness, and `isConnected` stays `true` while their sync is failing. `FacadeState.isSynced` and
  `facade.waitForSyncedState()` are gated through the unshielded wallet; a standalone shielded or Dust wallet is not.
- [#781](https://github.com/midnightntwrk/midnight-wallet/issues/781): An event-synced Dust snapshot resumes from an
  indexer database id, so it fails on every retry after the indexer behind its endpoint renumbers its events.
  Workaround: restore the Dust wallet from its seed, or use the projections Dust sync, which resumes from a block
  height.
- [#893](https://github.com/midnightntwrk/midnight-wallet/issues/893): The Dust wallet prices `feeBlocksMargin` on the
  proof-erased transaction, so the margin it pays falls short of the configured number of blocks. Workaround: configure
  a larger `feeBlocksMargin`.
- [#885](https://github.com/midnightntwrk/midnight-wallet/issues/885): A sender's shielded transaction-history entry can
  briefly show no spent coins after a transfer, and can stay that way if the wallet stops between two sync batches.
